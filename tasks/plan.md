## 修复决策

| 决策 | 理由 | 主要落点 |
| --- | --- | --- |
| F1：布局预检覆盖所有 memory MEMID，遇冲突拒绝 | cell 名称不能代表 Verilog 数组名称；失败必须发生在修改设计前 | `transport.cc` |
| F3：从原始 FF 类型识别无时钟 aload/SR latch | 修正 SR 分类，同时保留常量 D latch 身份 | `monitor_plan.cc` |
| F2：保留既定观测能力，正式要求插装后映射 | 保持原始 cell/port 身份，并统一支持性与最终导出契约 | `monitor_plan.cc`、导出回归、主设计/帮助 |
| F4：单命令摘要上下文，按 SCC 合成依赖哈希 | 消除逐根传递闭包重复计算，保留循环和过期检测 | `structural_digest.cc`、snapshot、`cellfilter.cc` |
| 独立语义表、raw memory 对照、故障注入 | 已有全部回归不能捕获 `has_sr` 错误，测试成功不足以关闭问题 | `tests/cellfuzz/` |

以上为推荐实施决策；如果类型矩阵证明某类无法通过正式导出流程，应记录具体证据和必要设计变更，不能悄悄缩小支持集合或改用未记录的额外步骤。

## 风险与处理

| 风险 | 处理 |
| --- | --- |
| memory 是否被选中影响占名检查 | 使用全量原始作用域；增加未选/关闭观测的碰撞用例 |
| 映射改变内部结构或引入最终接口偏差 | 插装后才映射；检查最终 Verilog 的公共接口、值和 manifest 位段 |
| 摘要提速降低变化敏感性，或缓存跨命令失效 | 保留完整局部记录；命令内上下文；恢复时重新计算；测试循环、clone 和依赖变化 |
| 版本变化被误认为随机不稳定 | 明确内部版本 1→2；同一新版本内校验确定性；不固定旧摘要字面值 |
| 测试与生产共享同一错误 | 手写期望、raw 输入对照和定点故障注入同时使用 |
| 时序或四态能力被夸大 | 记录输入域、步数、初始化和 X/Z 假设；不将有限验证写成完整证明 |

## 实施时需要核实的细节

- T3 要完成所有接受类型的导出能力表；本手册仅确认 `$fa` 的推荐流程可导出，不代表所有类型已经验收。
- T7 要逐项界定 `$mem`/`$mem_v2` 的合法归一化差异，不能通过 gold 调用 `Mem::emit()` 自动认定等价。
- 性能判定以操作次数为硬证据，墙钟和内存比较保留运行环境与样本；不承诺跨机器绝对耗时。

这些是任务中的研究和验证工作，不应通过降低验收标准跳过。实现范围继续以现有首版能力为限。
